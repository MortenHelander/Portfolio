## Better week!

Week 7 has been a much better week than week 6! I've realized that many other programs and also specifically chess API's use a mixture of REST and websocket to create their program. The stateless REST is used for calling creations or updates on the game / board state and websocket is used to have a real time connection where users can see the others moves without refreshing constantly. This breakthrough has given me much more confidence and motivation in this weeks work.
This week we learned about Ghirkin, hamcrest, Rest-assured 
The Rest-assured tests have been a fun and benneficial addition to confirming the functionallity of the API. Until this project tests have been feeling a bit like extra added work with little to no good reason of ressource distribution. But now seeing how calling the endpoints with expected success or failure and either confirming it works or discovering bugs and fixing them have actually been the coolest part of the proccess. This makes me want to try experiencing with TDD (test driven development) in the future! Our teacher told us to hold back with this design pattern until we're more experienced but for the next project (or a few projects into the future) I'll definetly give it a shot. Designing the tests first and then writing the code to get the test to pass makes a lot more sense now.
I'm at a point where the API is almost functional, the last day of this week we learned about Websockets and Webhooks and I've known from the start that Websocket is something I at least wanna try to implement, so I hope next week I can get it to work. One of my co-students also need it in his project and I'm looking forward to collaberating with him. I've enjoyed working solo and managing my own time and setting my own goals for this project, but I can't honestly say I don't miss sparring and sharing knowledge with other people as well.
